3 · Pinned row: operable jump implemented

  • Option chosen: operable jump (not the non-interactive fallback). The list is a plain scroll container and the jump is a deterministic scrollTop assignment, so it can be implemented reliably here.
  • The pin is role="button" with tabindex="0", an onClick handler, and onKeyDown for Enter and Space (Space's default page scroll is prevented). Its name states what it does. Focus ring: 2px ink outline, inset, in the same ink language as the YOU row.
  • A real server would load the page of rows around position 1,284; the sample window 1,270–1,298 stands in for that fetch. Loading of that page is not designed (assumption A2).
  • No way back to the top is added, since that would be a new interaction outside the brief.

4 · Row-scale tier tokens — PROPOSALS for owner review

S46 status: S46 (Tier & Division presentation) has been delivered since this revision was authored — it landed as part of the S48–S50 placement-flow package and is merged to origin/main (commit 9445964). It carries its own tier-token proposal, so these two treatments should be read together. They agree on Gold. S46 Gold is #E6D585 = oklch(.869 .102 97.7); the Brass default below is oklch(.761 .100 95.2) — the same hue and the same chroma, with S46 sitting 0.11 lighter in L. ΔE between the two is 10.9, and both are ΔE 12 from the Match-King crown #E8A33D (oklch(.765 .140 72.9), a distinctly more orange hue at higher chroma). So the direction was arrived at independently twice; the open question is only lightness, not hue. Nothing approved is overridden and no shared token is changed by this file. Everything below is a proposal, and the merged S46 decision supersedes it. Neither treatment uses tier artwork; both are CSS shapes.

VariantoklchΔE vs #E8A33D (Match-King)on surfaceon surfaceHigh
  • Gold — Brass oklch(.76 .10 95) (default) and Antique oklch(.70 .085 85): lower chroma and a hue about 13–23° more yellow than the crown's amber, so both read as aged brass rather than lime. Not #E8A33D, no crown glyph. Shape stays the hexagon, a flat 18px row-aligned token beside the name, while the Match-King crown is a glyph on the avatar. Antique sits closest to Bronze (oklch(.62 .09 50), a circle); the shape and ~.08 lightness gap keep them apart, but check this at a glance on device. Straw is the revision-1 value, kept for comparison.
  • Royal — Muted oklch(.62 .10 300) (default) and Deep oklch(.54 .09 302): lower chroma than the revision-1 violet (.17), a dusty aubergine-violet. The octagon shape and the cool hue keep the second-highest rung away from the warm near-black + brass room skin, which satisfies the §4.1.4 item 5 clause (Royal is the app's art direction). Deep is the quietest; it is measured above against both surfaces. No green anywhere (“blue-gold, no green felt”).
  • Both are non-text shapes; the tier name beside them stays ink.
  • The owner's “charcoal, deep-green, brass” description does not match the Foundation (warm near-black + gold/brass, no green). Worked from the Foundation.

7 · Season display format

§4b.7 says a season has an ID, a start and an end. There is no label field and no season code in the repository, so “Autumn 2026” cannot be shipped. The season.id binding and {season.id} placeholder are retained in the chip and column, matching S54. Both now read one constant (SEASON_TOKEN), so swapping in a label is a one-line change. Supporting labels later needs an approved label field on the season document and an owner ruling on the labelling scheme.

8 · Verification (measured on this page at load)

CheckResult

The Arabic font check probes weight 600 and passes the sample character م. This matters: Google Fonts serves Noto Naskh Arabic as five unicode-range subsets, and only the Arabic subset is ever fetched because no Latin text uses this family. check() without a text argument requires all subsets to be loaded, so it reports a false negative; with the Arabic character it reports loaded. Not performed by this script: console errors, git branch and docs/design/ placement.
