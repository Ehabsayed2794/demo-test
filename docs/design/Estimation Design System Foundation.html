Estemshan · Design System Foundation

§4.1 token foundation and §4.2 component library, specified as live CSS custom properties on one canvas so a Figma pass can be read off section by section. Mobile scale (390 dp frames, body ≥14, play-critical ≥16). Regions: 01 Tokens · 02 Contrast · 03 Core controls · 04 Player and table · 05 Cards and hand · 06 Feedback · 07 Gap resolutions · 08 Provenance.

Source status. Native tokens come from the eight EstemshanTheme.kt colours supplied by the owner (Background, Surface, SurfaceHigh, Gold, GoldDim, Ink, InkDim, Error) plus onPrimary = black. They are not read from web files. pill, goldHi, goldLow, redSuit and inkFaint do not exist in Kotlin; they are web-only and adding them to native is scheduled work. Anything unconfirmed is marked UNVERIFIED in region 08. Both region-07 decisions are resolved: the primary button keeps the documented 3-stop gradient with its label on a Gold chip, and redSuit is unified to #E0545B across cards and suit chips.

05 · §4.2.2 CARD · TOP PRIORITY

Card and hand

One Card component and one Hand treatment. The same hand renders in Bidding (S12–S15) and Table (S19–S22), including RESOLVING and round-DONE, so the hand no longer vanishes. Ranks are mono, ≥16 dp.

Card face · 13 ranks × 4 suits + SANS

Card states

Blue-gold card back · drawn

Deep blue ground (backBlue #12284A), gold hairline frame, goldDim lattice and a central gold lozenge. No green felt anywhere. Back sits at the same 1:1.4 ratio and 8 dp radius as the face, so a played-card stack and a hand share one silhouette.

One hand treatment, five contexts (390 dp)

Hand rules. 13 cards, 52 dp wide, 26 dp overlap, rank index always in the exposed left strip. Legal card lifts 10 dp with a goldDim hairline; illegal cards take the disabled hatch. RESOLVING dims the whole hand to 60% for the 900 ms beat and keeps it visible. Round-DONE keeps the 13 slots as dashed ghosts, so the hand area never collapses.

07 · §4.1.4 GAPS 1–4

Gap resolutions

Each block shows the decision and the reasoning.

1 · King vs Koz

REJECTED · gold vs goldDim
KINGKOZ
ADOPTED · gold crown vs koz shield
KINGKOZ
At table scale (blur):
KINGKOZ
KINGKOZ

Decision: introduce a distinct Koz token, koz #9C8FD0. gold and goldDim share one amber hue and differ only in lightness, so in peripheral vision both read as “gold badge”. The cool lavender sits opposite amber on the hue wheel, passes 4.5:1 on all three grounds, and the badge also changes shape (filled crown pill vs outlined shield). Separation does not rely on colour alone. goldDim stays in the system for dim rings and borders.

Constraint for the Ranked pass (§4.3.9): gold #E8A33D is the Match-King badge. If the Koz token is not approved, goldDim #A8742A is the Koz badge. Either way the future Gold tier must not reuse the crown glyph or gold-for-King semantic, or “Gold” collapses into “King” on one seat. Rank King (19th rung, no divisions) and Match King (first place in one match) are different things; never render King as III/II/I.

2 · Timer ring states

Running 3 dp gold arc, drains clockwise. Low-time 6 dp error arc, 4 ticks, pulse. Expired 3 dp dashed inkFaint ring, no arc, static. Stroke weight and pattern change, so the state reads in peripheral vision with the digits hidden (right-hand set). The low threshold is 5 s; the pulse is 600 ms and stops on expiry.

3 · Vote language

One affirmative accent: affirm #69C87E (the web client’s legal-move green). Negative: error (#F25555 passes as text and fill). Neutral and disabled: pill ground with inkFaint. Gold is reserved for primary actions and selection, so a gold button never means “vote yes”. Labels always carry the word, so colour is secondary.

4 · Card back

Owner direction: blue-gold, no green felt. Back uses backBlue #12284A with backBlueHi #244B7E lattice highlights and a goldDim/gold frame, drawn in SVG so it scales from the 52 dp hand to the 34 dp trick pile. In peripheral vision it separates from the ivory face by ground value alone.

5 · Primary button gradient RESOLVED · documented 3-stop + Gold-chip label

Roadmap §4.1.1 documents #FFF3DA → #E8A33D → #1A1208 at 160°, and that gradient is kept exactly as specified. Because onPrimary is black, no single label colour passes along it (black on #1A1208 = 1.13), so the approved treatment keeps all three stops and sits the label on a solid Gold chip — black on Gold 9.74 — letting the chip carry contrast while the gradient remains as the button’s rim. This is how Button / Primary in region 03 now renders.

6 · redSuit RESOLVED · #E0545B

The red suit appears on the ivory card face and as a glyph on near-black surfaces (bid summaries, suit chips), so one token must serve both. No single red passes 4.5:1 on both grounds; the corner index is ≥16 dp at weight 700, so the 3:1 large-text standard applies there. #E0545B is adopted as the single redSuit token — 3.34 on ivory (passes 3:1) and 4.61 / 5.25 on the dark grounds (passes 4.5). Cards (.card.r) and suit chips (.chip.red) now read the same --redSuit custom property.
