# Changelog — Sprint 3.5: Deck Implementation & Engine Integration

## Added
- `design-ui/engine/deck.js` — the missing `Deck` module `dealer.js` has always depended on (confirmed genuinely missing, not a naming/loading/export bug, by Sprint 3.4.5's audit). Reuses `cards.js` exclusively for suit/rank/card-shape — duplicates none of it. Public surface: `new Deck()` (builds a fresh, full, unshuffled 52-card set), `deck.shuffle(rng?)` (Fisher–Yates, in place; `rng` is an optional injectable random source defaulting to `Math.random`, resolving the one open design gap the Sprint 3.4.5 audit flagged), `deck.draw()` (removes and returns one card; throws a clear error if the deck is already empty), `deck.remaining()`, `deck.reset()` (rebuilds a fresh 52-card set with brand-new card objects). Instantiated per deal (`new Deck()`), not a shared singleton.
- `docs/architecture/GameEngine.md` — new document explaining the `Cards → Deck → Dealer → GameSession` layering and each layer's ownership boundary, per this sprint's explicit deliverable requirement.
- `tests/deck.test.cjs` — 39 new real, executed automated tests (loading the actual `cards.js`/`deck.js`/`dealer.js` files, no mocking of the engine itself): 52 unique cards on construction, exact combo coverage (no missing/extra), shuffle preserves the multiset and changes order, a deterministic-RNG test proving the shuffle algorithm is genuinely Fisher–Yates (exact expected permutation, not just "order changed"), draw removes exactly one card and never repeats within a deck, remaining() decreases correctly across multiple draws, draw() on an empty deck throws a clear error, reset() rebuilds a correct fresh 52-card deck with brand-new card objects, `Deck`'s public surface is exactly the required four methods (no gameplay logic leaked in), and `Dealer.dealHands()`: 4 hands, 13 cards each, 52 cards consumed, no duplicates, no missing cards (exact 52-combo coverage), correct owner stamping, correct display sort, repeatable across calls, and the pre-existing `seatOrder` override still works.
- `docs/reviews/Engine_Dependency_Audit_3.4.5.md` — the Sprint 3.4.5 audit report this sprint acts on (was pending, uncommitted per that sprint's explicit "do not commit unless requested" instruction; committed together with this sprint's work).

## Changed
- `design-ui/engine/dealer.js` — the minimum change required to consume the new `Deck`: `dealHands()`'s body now does `var deck = new Deck(); deck.shuffle();` then `deck.draw()` in its existing 13×4 loop, instead of the old, never-working `Deck.reset(); Deck.shuffle(); Deck.deal(1)[0];` singleton calls. Nothing else in this file changed — same `DEAL_ORDER`, same `SEAT_ROLES`, same seat-order-override parameter, same return shape, same display sort. Header comment updated to record the Sprint 3.5 change and point at the audit.

## Not changed (verified via `git diff --stat`)
- `design-ui/engine/cards.js` — reused as-is, per the explicit "do not duplicate card/suit/rank definitions" requirement.
- `design-ui/engine/bidding-engine.js`, `design-ui/engine/table-engine.js`, `design-ui/engine/scoring-engine.js`, `design-ui/engine/session.js` (`GameSession`), all `game-state.js` copies (`GameState`) — none touched; no unavoidable import/reference was found to require it. Both `bidding-engine.js` and `table-engine.js` already consumed hands exclusively through `GameSession.ensureHandsDealt()`, which was already exactly compatible with `Dealer.dealHands()`'s return shape (confirmed by the Sprint 3.4.5 audit) — no change was needed on that side of the chain.
- No Firestore/Services/UI file (`room-service.js`, `match-service.js`, `session-service.js`, `player-service.js`, `firestore.rules`, any screen's HTML/CSS) — this was an engine-only sprint.
- No game rule, bidding rule, or scoring rule was changed — `deck.js`/`dealer.js`'s changes are purely mechanical (deck state/behavior and its consumption), not rules logic. Verified by `tests/deck.test.cjs`'s explicit coverage of the full deal's correctness and by the diff sweep above.
- `MatchService` was **not** connected to `Deck`/`Dealer` — per the brief's explicit "Do NOT connect Deck to MatchService yet." `matches/{matchId}.gameState` remains the Sprint 3.4 `{initialized:false, todo:"..."}` placeholder, unchanged.
- No additional missing engine dependency was discovered beyond `Deck` itself — the integration proceeded cleanly once `Deck` existed (see `tests/deck.test.cjs`'s `Dealer.dealHands()` coverage, all passing on the first real run).
