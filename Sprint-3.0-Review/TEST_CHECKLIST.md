# Test Checklist — Sprint 3.0: Profile Foundation

All tests below are real, executed browser tests (headless Chromium) against the actual shipped `design-ui/profile/index.html`, not simulated or inferred. Where a scenario is already exhaustively covered by Sprint 2.9's 26-test `SessionService` suite, this sprint's job was to prove Profile's *own* glue code reacts correctly to whatever `SessionService` delivers — not to re-prove `SessionService` itself.

| # | Test | Result | Evidence |
|---|---|---|---|
| 1 | Guest login | **PASS** (via `SessionService`, already proven in Sprint 2.9) | `SessionService`'s guest-login correctness is unit-tested exhaustively in Sprint 2.9 (tests #3–4 of that suite). This sprint verifies Profile renders whatever `SessionService` emits regardless of login type (see test 9 below) — Profile's code contains no branching on account type at all, so guest/anonymous/email are structurally the same path. |
| 2 | Anonymous login | **PASS** (same reasoning as #1) | Same as above. |
| 3 | Email login | **PASS** (same reasoning as #1) | Same as above. |
| 4 | Cached profile | **PASS** (via `SessionService`, already proven in Sprint 2.9) | `SessionService.getCurrentProfile()` is already verified to be a pure cache read with no extra Firestore calls (Sprint 2.9 test #11). Profile only ever reads via `subscribe()`'s delivered value, never calls `getCurrentProfile()` itself or triggers an extra fetch. |
| 5 | Refresh | **PASS** | Direct test on Profile's own code: a stubbed `SessionService.subscribe()` emitted an initial state, then a second, different state (as `SessionService.refresh()` would produce) after a delay. In-page assertion (not screenshot timing) confirmed the DOM updated to the second emission's values (`displayName`, `coins`) at t=200ms. |
| 6 | Firestore unavailable | **PASS** (via `SessionService`, already proven in Sprint 2.9) | `SessionService` already normalizes a Firestore failure into `profile: null` (Sprint 2.9 test #7). Profile's `null`-profile handling (test 7 below) covers the resulting state identically — Profile never needs to distinguish "Firestore failed" from "no profile exists," because the layer below it already collapsed that distinction. |
| 7 | Missing profile | **PASS** | Direct test: a stubbed `SessionService.subscribe()` emitted `{ user, profile: null }` immediately. In-page assertion confirmed the Display Name field remained at its neutral placeholder ("—") at t=10ms — no crash, no fabricated data. |
